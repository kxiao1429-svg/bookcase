# 把书库挂到联想个人云上

这份文档对应 **Bookcase 2.0 私有云版**。目标是：

- 书库服务跑在联想个人云（NAS）上，7×24 开机就能用；
- 手机连上同一个网络，打开网页就能**把手机里的电子书上传备份到 NAS**；
- 也能**从 NAS 下载**到手机，或者直接在网页里读 EPUB；
- 书本身存在 NAS 的共享目录里，联想「数据守护者」App 也能看到同一批文件。

---

## 0. 先选路线

联想个人云不是群晖那种开放 NAS，能不能装第三方程序，取决于型号和固件。先对号入座：

| 你的情况 | 走哪条路线 | 难度 |
| --- | --- | --- |
| **T2（非 Pro）** | **官方明确不支持 Docker**。优先 **路线 C（电脑 + Samba，最稳）**；能开 SSH 且机器上有 python3 就走 **路线 B** | 低 / 中高 |
| T2 Pro（Intel x86，固件较新） | **路线 A：Docker** | 中 |
| A1 / T1，能通过「远程协助」开 SSH | 有 Docker 用路线 A，没有就用 **路线 B** 直接跑 Python | 中高 |
| 不想动系统 / 固件锁死 / 没有 Python | **路线 C：书库跑在电脑上，书存 NAS 共享目录** | 低 |
| 只是想先看看界面和功能 | 先在这台 Windows 电脑上跑，见文末「本机试跑」 | 低 |

> **T2 用户先看这一条**：联想官方 2024-12 在社区明确回复「T2 因架构问题，不会支持 Docker」；T2 是 ARM（Realtek RTD1296，64 位 Cortex-A53），T2 Pro 才是 Intel x86。所以网上 T2 Pro 的 Docker 教程不能套用到 T2 上。你的 T2 现实路线只有两条：**路线 C（电脑 + Samba）** 或 **路线 B（SSH + Python）**。
>
> 说明：联想个人云没有公开的第三方 API。所谓「上传到联想云」，实际是**把文件写进 NAS 的磁盘/共享目录**，再由联想自己的 App、Samba、备份功能去同步。所以书库要么跑在 NAS 上（路线 B），要么跑在一台按需开机的电脑上、把书库目录指向 NAS 共享盘（路线 C）。

---

## 1. 准备工作

### 1.1 查型号、固件、CPU 架构

手机打开「数据守护者」（部分版本叫「联想个人云」）App：

- 【我的】→【设备管理】→【设备信息】：记下 **IP**、**UID**、**MAC**。
- 记下固件版本。只有 T2 Pro 需要较新的固件才有 Docker；T2 不支持 Docker。

能 SSH 的话再确认架构：

```bash
uname -m
# aarch64 → 64 位 ARM：T2 / A1（T2 没有官方 Docker）
# x86_64  → Intel：T2 Pro（可跑 Docker）
# armv7l  → 32 位 ARM：老机型，Docker 基本别想，走路线 B/C
```

### 1.2 给 NAS 固定 IP

联想个人云不能在机器里设静态 IP。到路由器后台做 **DHCP 静态绑定**（MAC → IP），否则重启后 IP 变了，手机书签就失效。

### 1.3 找到「书库目录」的真实路径

书最终要放在 NAS 的共享目录里。SSH 进去找：

```bash
df -h                 # 看大容量磁盘挂在哪
ls /sata              # 联想个人云的数据盘常见位置
ls /sata/.storage
```

社区资料里，联想个人云的 Docker 根目录是 `/sata/.storage/docker`，个人空间/共享空间一般也在 `/sata/.storage` 下面。以你机器上实际看到的为准。

## 2. 路线 A：Docker（仅 T2 Pro / x86 机型）

> **T2（非 Pro）请直接跳过这一节。** 联想官方 2024-12 明确回复 T2 因 ARM 架构不会支持 Docker；下面的官方 Docker 步骤只适用于 T2 Pro（Intel x86）。

### 2.1 把 Docker 跑起来

**T2 Pro（官方 beta）**

1. 升级固件到最新；
2. Windows 上更新「数据守护者 / 联想个人云」PC 客户端；
3. 在 PC 客户端里找到 Docker 功能并启用（手机 App 里没有）。

**老机型 A1 / T1（社区做法，风险高；T2 官方明确不支持，不建议尝试）**

部分联想个人云内置了 Docker，只是启动脚本被禁用了：

```bash
docker image ls
# 如果报 Cannot connect to the Docker daemon，说明没启动
cat /etc/init.d/S60dockerd
```

把 `do_start` 里的 `exit` 注释掉，然后：

```bash
/etc/init.d/S60dockerd restart
docker image ls
```

> 这一步会改系统文件，固件升级可能被重置；不熟悉 Linux 就别硬上，走路线 C 更省心。T2 上没有官方支持，即使 daemon 能起来，也可能因为内核/存储驱动跑不动容器。

### 2.2 把项目放到 NAS 上

在 Windows 上（项目目录的上一级）：

```powershell
scp -r .\bookcase root@192.168.1.x:/sata/.storage/docker/bookcase-src
```

或者用 Samba 把目录拷进去，再 SSH 操作。

### 2.3 配置

```bash
cd /sata/.storage/docker/bookcase-src
cp .env.example .env
vi .env
```

至少要改这三项：

```ini
BOOKCASE_TOKEN=一串足够长的口令
BOOKS_DIR=/sata/.storage/你的电子书目录
DATA_DIR=/sata/.storage/docker/bookcase
```

- `BOOKS_DIR`：NAS 上真正放书的目录。想让它出现在「数据守护者」App 里，就指到你的个人空间/共享空间目录。
- `DATA_DIR`：数据库、封面、上传临时文件。**必须持久化**，别放容器里。

### 2.4 构建并启动

NAS 能联网：

```bash
docker compose up -d --build
# 老版本 Docker 用：docker-compose up -d --build
docker logs -f bookcase
```

看到类似输出就成功了：

```
Bookcase 2.0.0 已启动: http://0.0.0.0:8765
局域网访问: http://192.168.1.x:8765
```

没有 compose 插件（`docker compose` 报 unknown command）就直接 `docker run`：

```bash
docker build -t bookcase:local .
docker run -d --name bookcase --restart unless-stopped \
  -p 8765:8765 \
  -e BOOKCASE_TOKEN='你的口令' \
  -e BOOKCASE_ROOTS=/books \
  -e BOOKCASE_UPLOAD_DIR=/books/上传 \
  -e BOOKCASE_AUTO_SCAN_MIN=10 \
  -v /sata/.storage/你的电子书:/books \
  -v /sata/.storage/docker/bookcase:/data \
  bookcase:local
```

更新版本：`docker rm -f bookcase`，重新 build + run；数据库在 `/data` 卷里，不会因为换容器丢。

### 2.5 如果 NAS 不能联网 / 拉不动镜像

在 Windows 上构建对应架构的镜像再导入（需要 Docker Desktop）：

```powershell
# T2 Pro（Intel x86_64）
powershell -ExecutionPolicy Bypass -File .\deploy\build-arm64-image.ps1 -Platform linux/amd64 -Tag bookcase:amd64 -Out bookcase-amd64.tar

# 其他 ARM64 机型（如果 Docker 能跑）
powershell -ExecutionPolicy Bypass -File .\deploy\build-arm64-image.ps1 -Platform linux/arm64 -Tag bookcase:arm64 -Out bookcase-arm64.tar
```

把生成的 tar 传到 NAS 后：

```bash
docker load -i bookcase-amd64.tar    # 或 bookcase-arm64.tar
```

然后把 `docker-compose.yml` 里的 `build: .` 换成对应镜像：

```yaml
image: bookcase:amd64    # T2 Pro；ARM 机型换成 bookcase:arm64
```

再 `docker compose up -d`。

### 2.6 用 Portainer 也行

如果习惯图形界面，装个 Portainer（`portainer/portainer-ce`），把镜像、端口 8765、两个卷 `/books` 和 `/data`、环境变量 `BOOKCASE_TOKEN` 填进去即可。

## 3. 路线 B：开 SSH，直接跑 Python（T2 没有 Docker 时的首选）

适合没有 Docker、但能拿到 root 的 A1 / T1 / T2。**改系统有风险，先备份重要数据。**

T2 是 aarch64，只要能开 SSH 并且系统里有 `python3`，这条路就能让书库直接跑在 NAS 上，不依赖 Docker。

### 3.1 开启 SSH（社区方法，A1 实测）

1. 手机 App【我的】→【远程协助】→ 开启（固件太旧可能没有这个入口，先升级）。
2. 电脑上：

```bash
ssh admin@192.168.1.x
cat /opt/conf/user/assist/conf.json
```

里面的 `ssh_pwd` 就是 root 密码。然后：

```bash
ssh root@192.168.1.x
passwd root          # 第一件事：改成自己的密码
touch /opt/conf/user/enable_ssh   # 永久开启 SSH
```

3. 想用普通用户提权：编辑 `/etc/passwd`，把对应用户的 UID/GID 改成 0。

> 注意：有人的设备用这种方法 root 登录一次后密码就失效，原因是根文件系统变成只读；必要时 `mount -o rw,remount /`。不同固件差异很大。

### 3.2 装书库

先确认版本（联想不公开固件软件包清单，不同固件可能没有 Python 或版本过旧；书库要 **Python 3.7+**）：

```bash
python3 -V
uname -m
```

建议装到硬盘目录，书也放硬盘（别塞 8GB eMMC）：

```bash
# 本机（Windows）
scp -r .\bookcase root@192.168.1.x:/sata/.storage/bookcase

# NAS 上
cd /sata/.storage/bookcase
chmod +x start.sh stop.sh deploy/install-ssh.sh
# 轻量模式：不装 PyMuPDF，PDF 只按文件名收录，EPUB 封面正常
INSTALL_PDF=0 BOOKS_DIR=/sata/.storage/books \
  sh deploy/install-ssh.sh /sata/.storage/bookcase
```

脚本会：检查 python3 → 建 `data/`、书库目录 → 生成带随机口令的 `config.json` → 装 PyMuPDF（`INSTALL_PDF=0` 则跳过）→ `start.sh`。

输出里的「访问口令」记下来，手机登录要用。

> 负载很小：空闲约 30–50MB 内存、<1% CPU；首次扫描 EPUB 是单核轻活，扫描 PDF 封面才是唯一的重活。T2 上建议用 `INSTALL_PDF=0` 轻量模式，并在备份完手动点一次扫描（`autoScanMinutes=0`）。`start.sh` 已用 `nice -n 19` 降优先级，不抢 Samba。

### 3.3 开机自启

有 systemd 的话：

```bash
cp /sata/.storage/bookcase/deploy/bookcase.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now bookcase
systemctl status bookcase
```

没有 systemd 就看 `/etc/rc.local` 或 `/etc/init.d/`，把 `/sata/.storage/bookcase/start.sh` 加进去。联想固件升级后自启项可能被重置。

### 3.4 常见坑

- **根目录只读**：`mount -o rw,remount /` 后再写文件。
- **没有 python3**：`python3 -V` 确认；没有就走路线 C。别在 NAS 上硬编译 Python。
- **pip 装不上 PyMuPDF**：EPUB 完全不受影响，PDF 只是没有封面和页数。

## 4. 路线 C：不装程序，书库跑在电脑上（T2 最稳）

最稳，适合先验证，或者 NAS 固件不给权限。T2 官方不支持 Docker、系统里也未必有可用的 Python，所以这条路线对 T2 往往是首选：**完全不改 NAS，只开它自带的 Samba**，书仍然存在联想云盘里。

### 4.1 打开 NAS 的 Samba

手机「数据守护者」App →【更多应用】→【Samba】→ 打开（管理员可以改密码）。官方说明默认账号是设备 UID，默认密码 `123456`。

### 4.2 Windows 映射网络驱动器

`Win + R` 输入：

```text
\\192.168.1.x
```

用 UID / 密码登录，把「个人空间」或某个共享文件夹映射成 `Z:`。

### 4.3 跑书库

在 Windows 上：

```powershell
cd D:\bookcase
python -m pip install -r requirements.txt
```

新建 `config.json`：

```json
{
  "roots": ["Z:\\电子书"],
  "uploadDir": "Z:\\电子书\\书库上传",
  "trashDir": "Z:\\电子书\\.bookcase-trash",
  "host": "0.0.0.0",
  "port": 8765,
  "token": "换成你的口令",
  "maxUploadMB": 4096,
  "autoScanMinutes": 10
}
```

然后双击 `start-windows.bat`，或：

```powershell
python server.py
```

手机浏览器打开 `http://电脑的局域网IP:8765`。

> **不需要 24 小时开着。** 备份或下载时开机跑一下，用完关掉即可；书始终在 NAS 上，电脑只是临时服务。只有想「人在外地也能随时访问」才需要常开设备（或把书库跑在 NAS 上，见路线 B）。

## 5. 手机怎么用

1. 手机连上家里的 Wi-Fi（和 NAS/电脑同一网段）。
2. Chrome 打开 `http://NAS的IP:8765`。
3. 输入访问口令。
4. 浏览器菜单 →「添加到主屏幕」，以后像 App 一样打开。

### 上传备份

- 点右上角 **＋** →「备份到云端」。
- **选择文件**：一次选多本 epub / pdf / mobi / azw3 / azw / fb2 / cbz / djvu。
- **选择文件夹**：整个书文件夹一起选（桌面 Chrome 支持；部分安卓文件选择器可能不显示文件夹，用「选择文件」多选即可）。
- 点开始后：先秒级预检，**云端已有的（同名同大小）自动跳过**，只传新的；服务端还会按文件内容再查一次重，重复的不会存第二份。
- 传完直接出现在书架，不用手动扫描。

如果书在 **Windows 电脑**上，用一条命令整批备份（自动跳过已有，断了重跑）：

```powershell
cd D:\bookcase
powershell -ExecutionPolicy Bypass -File .\deploy\upload-folder.ps1 -Folder "D:\我的电子书"
```

脚本会读 `config.json` 的端口和口令，逐个上传并显示进度；先加 `-DryRun` 可以只看会传哪些。

更底层的方式（curl，单文件）：

```bash
curl --data-binary @book.epub \
  -H "Authorization: Bearer 你的口令" \
  "http://NAS_IP:8765/api/upload?name=book.epub"
```

### 下载

- 单本：点任意一本书 →「下载到本机」，走浏览器下载，存到手机的 Download 目录。
- **按书单下载**：进书单 → 点「下载书单（N）」→ 浏览器会把整张书单的书打成一个 ZIP（里面还有 `书单.txt` 清单和缺失文件说明）。
- **整库备份**：设置页最下面「导出整个书架（ZIP）」，书 + 书单/标签/进度 `manifest.json` 一次带走。
- EPUB 可以点「开始阅读」直接在书库里读，进度自动记。
- 联想「数据守护者」App 里也能看到这些书（前提是 `BOOKS_DIR` 指到了它的共享目录；看不到就在 App 里刷新/重新扫描一次）。

> 打包下载是边读边发（HTTP chunked），不会在服务器上先生成一个同样大的临时 ZIP；书单很大时浏览器会显示「正在下载」，耐心等它开始即可。

### 想真正「自动备份」？

浏览器不能在后台偷偷扫手机存储，但可以组合出一个接近全自动的方案：

1. 手机装 **FolderSync**（或 Syncthing）：
   - 源：手机的 `Download` / `Books` 等目录，只筛电子书扩展名；
   - 目标：联想个人云通过 **Samba** 暴露的共享目录（账号 UID，密码按 App 里设置的）；
   - 触发：连上家里的 Wi-Fi 时自动单向同步。
2. 书库的 `BOOKS_DIR` 指到同一个共享目录，并把 `autoScanMinutes` 设成 10（Docker 里默认就是 10，即 `BOOKCASE_AUTO_SCAN_MIN=10`）。
3. 手机连上 Wi-Fi → FolderSync 把新书传进 NAS → 最多 10 分钟书库自动扫描完成，书架出现新书。

这条路线里，FolderSync 负责「传」，书库负责「索引、封面、阅读、下载」，比在浏览器里手动选文件更接近真正的自动备份。

### 让 DSH 帮你整理书库

DSH 不装在 NAS 上；它在电脑上通过书库 API 和 `Z:` 访问数据。挂好 NAS、启动书库后，可以用 `tools/bc.py` 读全量目录、归档重复书、批量建书单/打标签。完整说明和「思维环」书单模板见 **[AI 整理书单.md](<AI 整理书单.md>)**。

## 6. 外网访问（可选）

**不要**直接把 8765 端口映射到公网：这是 HTTP 明文，口令会在路上裸奔。

推荐顺序：

1. **Tailscale / ZeroTier**（最省事）：在跑书库的设备上装客户端，手机也装，加入同一个虚拟局域网，然后访问 Tailscale 分配的 IP。联想 NAS 装不了客户端的话，可以把 Tailscale 跑在 Docker 里，或者用路线 C 跑在电脑上。
2. **frp + 域名 + HTTPS**：frp 把 8765 映射出去，前面套 Caddy/Nginx 申请证书；反代记得放大 `client_max_body_size`（默认 1M 传不了书）。
3. 无论哪种，`BOOKCASE_TOKEN` 必须足够长，别用生日/123456。

## 7. 数据在哪、怎么备份

Docker 路线：

| 内容 | 容器内 | 宿主机（你的 `DATA_DIR` / `BOOKS_DIR`） |
| --- | --- | --- |
| 数据库 | `/data/library.db` | `.../bookcase/library.db` |
| 封面缓存 | `/data/covers/` | `.../bookcase/covers/` |
| 原书 | `/books/` | 你的电子书共享目录 |

- 备份 = 拷走 `library.db` + `covers/` + 书目录。
- 数据库记的是**容器内路径**（`/books/...`）。换挂载路径后，书可能显示「原文件已被移动」，重新扫描一次即可。
- 上传的临时文件在 `/books/上传/.incoming`，正常上传完会自动清掉；断电残留可以手动删。

## 8. 常见问题

**打开网页是登录页，输口令提示不对**
口令在 `config.json` 的 `token`，或 Docker 的 `BOOKCASE_TOKEN`。改完要重启服务。

**上传按钮点了没反应**
换个浏览器（Chrome/Edge）；确认选的文件扩展名在支持列表里；看页面底部有没有红色报错。

**传到一半失败**
- 文件超过 `maxUploadMB`（默认 4096 MB）会返回 413；
- NAS 空间不足会返回 507；
- 反代时改 `client_max_body_size` 和超时。

**手机打不开 NAS 的地址**
确认同一 Wi-Fi、路由器没开 AP 隔离、NAS 防火墙放行 8765；先用电脑 `curl http://NAS_IP:8765/api/health` 验证。
如果书库跑在 Windows 上，第一次启动时 Windows 防火墙会弹窗，要允许「专用网络」。

**Docker 起不来 / 镜像架构不对**
先确认型号：**T2（非 Pro）官方不支持 Docker**，不要在这上面耗时间，走路线 B/C。T2 Pro 是 Intel x86_64（镜像用 `linux/amd64`）；A1/T1 等 ARM 机型如果 Docker 能跑，用 `linux/arm64`（老 32 位机型 `armv7l` 基本无解）。

**书在网页里有，联想 App 里没有**
`BOOKS_DIR` 指到 App 管理的共享目录；App 的索引可能需要重新扫描/重启。Docker 以 root 写入时，文件属主可能不对：

```bash
ls -ln /sata/.storage/你的共享目录 | head
chown -R 1000:1000 /sata/.storage/你的共享目录/上传   # UID 以已存在文件为准
```

**PDF 没有封面**
NAS 上 PyMuPDF 没装成功。EPUB 不受影响；想补就 `pip3 install pymupdf` 后重新扫描。

**固件升级后 Docker/SSH 没了**
社区玩法不受官方保证。升级前先记下配置，升级后按本文重来一遍；书和数据都在磁盘上，不会丢。

## 9. 本机试跑（不碰 NAS，先看效果）

Windows 上：

```powershell
cd D:\bookcase
python -m pip install -r requirements.txt
copy config.example.json config.json
# 改 roots 为你电脑上的书目录
python server.py
```

打开 `http://127.0.0.1:8765`。默认只监听本机；手机访问要把 `host` 改成 `0.0.0.0` 并设 `token`。
